# 🎯 Fireball / Ice Lance 발사 위치 수정

## 문제

Fireball과 Ice Lance가 발사는 정상적으로 되었지만  
**화면 중앙의 조준점과 실제 투사체의 궤적이 맞지 않는 문제**가 있었다.

`firePos`의 위치를 여러 번 조절했지만 근본적으로 해결되지 않았다.

또한 발사 방향을 조준점의 Raycast 위치로 강제로 보정해보니  
가까운 위치에서 투사체가 휘어 들어가는 것처럼 보이는 문제가 생겼다.

## 해결

실제 투사체가

- 카메라 중앙선에서 생성되고
- 카메라의 정방향으로 그대로 이동하도록

발사 구조를 수정했다.

`firePos`는 카메라의 중앙선 위에 배치하고,  
실제 투사체는 조준점이 가리키는 방향과 동일한 방향으로 직선 이동하도록 했다.

### 결과

- 가까운 물체 조준 정상
- 멀리 있는 물체 조준 정상
- Fireball과 Ice Lance의 발사 기준 통일
- 화면 중앙 조준점과 실제 공격 판정 일치

# ❄️ Ice Lance

Ice Lance는 단순한 공격 마법이 아니라  
**대상의 물리 상태를 변화시키는 냉각 마법**으로 만들고 있다.

## Frozen 상태

Ice Lance 폭발 범위 안에 있는 Object의 Collider에  
얼음용 `Physic Material`을 적용한다.

얼음용 Physic Material은 마찰력을 매우 낮게 설정한다.

결과적으로 얼어붙은 물체는:

- 처음 움직이기 쉬워지고
- 한번 움직이면 더 오래 미끄러지며
- Fireball 등의 힘을 받았을 때 평소보다 크게 이동한다.

### Physic Material

Frozen 상태에서는 다음 값을 기준으로 테스트한다.

- Static Friction → 매우 낮음
- Dynamic Friction → 매우 낮음
- Bounciness → 0
- Friction Combine → Minimum

# 🔥 Fireball × Ice Lance

Fireball에는 기존의 폭발 효과에 더해  
**얼어붙은 물체를 녹이는 역할**도 추가하기로 했다.

현재 Prototype에서는 일반 Object의 기본 Physic Material을 사용하지 않기 때문에,

### Ice Lance

`None → Frozen Physic Material`

### Fireball

`Frozen Physic Material → None`

의 단순한 구조로 구현한다.

즉,

> ❄️ Ice Lance → 마찰 감소  
> 🔥 Fireball → 얼음 해제 + 폭발

이라는 마법 간 상호작용이 생겼다.

# 🪄 Levitate 물리 규칙

Levitate를 단순하게 `Gravity OFF`로 만드는 것만으로는 부족하다고 판단했다.

Levitate 상태에서도 **물체의 질량은 그대로 유지**하기로 했다.

### Levitate 상태의 규칙

- 중력 제거
- 질량 유지
- 바닥과 접촉하지 않으므로 지면 마찰 제거
- 외부 힘에는 기존 질량에 따라 반응
- 공중에서 계속 이동하지 않도록 공기 저항 적용

예를 들어 같은 Fireball 폭발을 맞아도:

- 가벼운 물체 → 크게 이동
- 무거운 물체 → 적게 이동

하도록 만든다.

하지만 공중에서는 바닥 마찰이 없기 때문에  
무거운 물체도 지상에 있을 때보다는 움직이기 쉬워진다.

또한 한번 밀린 물체가 공중에서 무한히 움직이지 않도록  
Levitate 상태에서는 Drag 또는 별도의 감속 처리를 사용할 예정이다.

# ⚖️ 게임의 핵심 컨셉 정리

게임의 핵심은 단순한 마법 퍼즐이 아니다.

> **불법적으로 보이는 일을 직접 불법적으로 수행하는 것이 아니라,  
> 마법과 게임 속 법/규정의 모호함을 이용해 규정을 위반하지 않고 목적을 달성한다.**

따라서 퍼즐에서 특정 마법을 직접 요구하지 않는다.

### ❌ 좋지 않은 조건

> 물체를 얼리시오.

이 경우 사실상 Ice Lance를 사용하라는 문제와 같다.

### ✅ 원하는 조건

> 검사 시 물체의 온도는 0°C 이하여야 한다.

플레이어에게는 **결과만 요구하고 방법은 알려주지 않는다.**

Prototype 2에서는 다음 마법들을 중심으로 퍼즐을 구성한다.

| Magic | Effect |
| --- | --- |
| 🔥 Fireball | 폭발 / 밀어내기 / Frozen 해제 |
| ❄️ Ice Lance | 냉각 / 마찰 감소 |
| 🔄 Swap | 두 Object의 위치 교환 |
| ✨ Duplicate | Object 복제 |
| 🌀 Animate | Object가 스스로 움직이게 함 |
| 🪄 Levitate | Object를 공중에 띄움 |

퍼즐은 가능하면 특정 마법 하나만으로 해결되지 않고,  
여러 마법과 물리 시스템을 조합하도록 설계한다.

# 👥 Multiplayer

최대 플레이어 수는 **4명**을 목표로 한다.

하지만 퍼즐 자체는 플레이어 인원수에 의존하지 않도록 한다.

## 기본 원칙

### 1 Player

혼자서 모든 퍼즐을 해결할 수 있어야 한다.

### 2~4 Players

같은 퍼즐을 더 빠르거나 편하게 해결할 수 있다.

즉,

> 인원이 늘어나면 **해결 가능 여부가 바뀌는 것이 아니라 작업을 병렬로 할 수 있게 된다.**

---

## 피해야 할 구조

- 4명이 동시에 버튼을 눌러야 함
- 플레이어 2명이 동시에 마법을 사용해야 함
- 플레이어 숫자만큼 발판을 밟아야 함

이런 퍼즐은 인원수에 지나치게 종속된다.

대신,

> 플레이어가 아니라 **Object와 World의 상태를 조건으로 검사한다.**

예를 들어

`두 플레이어가 동시에 레버를 잡는다`

가 아니라

`두 레버가 동시에 활성화되어 있다`

를 조건으로 만든다.

혼자라면 마법을 이용해 하나를 유지한 뒤 다른 하나를 처리할 수 있고,  
멀티에서는 각 플레이어가 하나씩 담당할 수 있다.

# 🧪 Prototype 2 퍼즐 계획

Prototype 2에서는 우선 **5개의 퍼즐**을 만들어볼 예정이다.

## 🟢 Easy × 2

### 1. 반출하지 않고 반출하기

출입 제한 구역의 물체를 밖으로 가져와야 하지만  
해당 물체가 **출입구를 통과해서는 안 된다.**

→ 게임의 '규정을 문자 그대로 해석한다'는 개념을 학습시키는 퍼즐.

### 2. 직접 운전하지 않고 차량 이동

- 엔진 사용 금지
- 플레이어 직접 접촉 금지
- 지정 구역까지 차량 이동
- 마지막에는 정지 상태

→ 여러 마법과 물리를 이용해 같은 결과를 만들 수 있다는 것을 보여준다.

---

## 🟡 Normal × 2

### 3. 박물관 전시물 반출

목표 전시물을 외부로 가져와야 하지만

- 전시대가 비어서는 안 됨
- 내부 Object 개수를 유지해야 함
- 전시물 파손 금지

등의 조건을 동시에 만족해야 한다.

### 4. 위험물 운송

위험물을 다른 연구실까지 운송해야 한다.

검사 시:

- 일정 온도 이하
- 바닥과 접촉하면 안 됨
- 검사 영역 내부에 존재
- 일정 시간 정지
- 용기 파손 금지

등의 조건을 만족해야 한다.

---

## 🔴 Very Hard × 1

### 5. 완전 합법적 반출 시험

여러 규정을 하나의 방에 조합한다.

예시:

- 플레이어 출입 금지
- 시설 파괴 금지
- 중량 제한
- Object 개수 유지
- 동일한 샘플 2개 필요
- 냉각 상태 필요
- 바닥 접촉 금지
- 일정 시간 정지 필요

특정 마법을 사용하라고 요구하지 않는다.

어떤 팀은 4개의 마법으로 해결할 수도 있고,  
다른 팀은 6개를 모두 사용할 수도 있도록 만드는 것이 목표다.

# 💡 오늘의 설계 결론

오늘 가장 중요한 결정은 다음과 같다.

> **퍼즐은 마법을 검사하지 않는다.  
> 마법으로 만들어낸 World의 결과를 검사한다.**

그리고 난이도 역시

> 사용하는 마법의 개수

가 아니라

> **동시에 고려해야 하는 규칙과 상태의 수**

로 높여나간다.

이 구조가 제대로 작동한다면 플레이어마다 서로 다른 해결 방법이 나오고,  
멀티플레이에서는 자연스럽게 역할 분담과 예상하지 못한 상황이 발생할 수 있을 것 같다.
