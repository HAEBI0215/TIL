# 🎨 Perfectly Legal Magic

## 캐릭터 모델링 구조 결정

플레이어 캐릭터는 일반적인 애니메이션 캐릭터보다는
물리적인 움직임이 잘 드러나는 형태로 제작할 예정이다.

특히 게임에서 **Ragdoll Physics**를 사용할 계획이기 때문에
외형뿐만 아니라 관절 구조까지 고려해서 모델링해야 한다.

캐릭터는 이후 커스터마이징도 고려해 다음과 같이 파츠를 분리하는 방향으로 정리했다.

```text
Character
├─ Body
├─ Hat
├─ Cape
├─ Bag
└─ 기타 장식 파츠
```

기본이 되는 `Body`부터 제작한 뒤
나머지 장식 요소를 별도의 파츠로 추가하는 방식이다.

이렇게 하면 플레이어마다 모자나 가방 같은 요소를 바꾸기도 쉬워진다.

## 🦴 Ragdoll Physics 구조 이해

오늘 가장 확실하게 정리한 부분 중 하나는
**Blender의 리깅과 Unity의 Ragdoll은 서로 역할이 다르다**는 것이다.

### Blender

Blender에서는 Ragdoll 자체를 만드는 것이 아니라

* Armature 제작
* Bone 구조 설정
* 부모-자식 관계 설정
* Weight Painting
* 관절 위치 설정

등을 통해 **물리 캐릭터가 움직일 수 있는 기반 구조**를 만든다.

### Unity

실제 Ragdoll 물리는 Unity에서 처리한다.

```text
Blender

Mesh
+
Armature
+
Weight

        ↓ FBX

Unity

Rigidbody
+
Collider
+
Joint
+
Physics
```

Unity에서는 각 Bone에 Collider와 Rigidbody 등을 연결하고
관절 제한을 설정해 실제 물리 기반 캐릭터로 만든다.

따라서 Blender 단계부터

* 어깨
* 팔꿈치
* 골반
* 무릎

등의 관절 위치가 명확해야 한다.

# 🧪 Blender 모델링 테스트

## 캐릭터 머리 제작 시도

실제 Blender에서 캐릭터 머리부터 제작해보기 시작했다.

처음에는 기본 도형을 직접 수정하는 방식뿐만 아니라
Python을 이용해서 Mesh를 생성하는 방법도 테스트했다.

하지만 결과물이

* 모델이 보이지 않거나
* 좌표가 정상적으로 생성되지 않거나
* 단순한 Sphere 형태에 머무르거나
* 참고 이미지의 굴곡이 반영되지 않는

문제가 계속 발생했다.

특히 내가 원하는 캐릭터의 머리는 단순한 구가 아니라
실루엣 자체에 형태 변화가 있기 때문에

```text
Sphere 생성
→ Scale 조절
```

정도만으로는 원하는 결과를 만들 수 없었다.

## 🤖 AI 기반 Blender 자동 모델링 테스트

ChatGPT Desktop과 Blender를 연결해
AI가 Blender를 직접 조작하면서 모델링하는 방식도 검토했다.

모델링 명령을 더 자세하게 작성하기 위해

* 사용할 Blender 버전
* 파츠 분리
* T-Pose
* Ragdoll을 고려한 관절
* 캐릭터 실루엣
* 모델링 순서

등을 구체적으로 명시하는 방식도 시도했다.

하지만 명령을 자세하게 작성해도 결과적으로는

> **기본 도형을 조합해서 캐릭터처럼 만드는 수준**

에서 크게 벗어나지 못했다.

원하는 캐릭터는 단순히

```text
Sphere + Cylinder + Cube
```

를 붙이는 것이 아니라
하나의 캐릭터로 자연스럽게 연결된 실루엣과 형태가 필요했다.

## 🔄 제작 방식 변경

여러 번 테스트한 결과
현재 AI에게 캐릭터 모델링 전체를 맡기는 것보다는

> **내가 직접 Blender 모델링을 하고 AI는 작업 방법과 문제 해결을 보조하는 방식**

이 더 현실적이라고 판단했다.

즉,

```text
AI가 모델 완성
```

이 아니라

```text
직접 모델링
    ↓
막히는 부분 확인
    ↓
AI에게 방법 질문
    ↓
직접 수정
```

방식으로 제작 방향을 바꿨다.

자동화가 항상 직접 제작보다 빠른 것은 아니라는 것도 느꼈다.

# 📚 Today I Learned

## 1. Ragdoll은 Blender와 Unity의 역할이 다르다

Blender에서는 물리 효과 자체보다
**Ragdoll이 제대로 움직일 수 있는 Mesh와 Bone 구조를 준비한다.**

실제 Rigidbody, Collider, Joint를 이용한 물리 처리는 Unity에서 담당한다.

---

## 2. 캐릭터 모델링은 기본 도형 조합만으로 해결되지 않는다

간단한 프로토타입 모델은 Primitive 조합으로 만들 수 있지만
특정 디자인의 캐릭터를 만들려면

* 실루엣
* 면의 흐름
* 굴곡
* 관절 위치

등을 직접 만들어야 한다.

특히 참고 이미지와 비슷한 형태를 만들려면
단순히 Sphere의 크기만 변경하는 것으로는 부족하다.

---

## 3. AI 자동화가 항상 더 빠른 것은 아니다

AI에게 작업을 자세하게 설명하는 데 많은 시간이 들어가는데
결과물이 원하는 수준에 도달하지 못한다면 오히려 직접 제작하는 것이 빠를 수 있다.

따라서 앞으로는

> **AI = 완성품 제작 도구**

보다는

> **AI = 제작 과정에서 막히는 부분을 해결하는 도구**

로 활용하는 것이 더 효율적일 수 있다.

---

## 4. 프로토타입에서는 그래픽보다 핵심 재미 검증이 먼저다

캐릭터를 완성하는 것도 중요하지만
현재 2차 프로토타입에서 가장 먼저 확인해야 하는 것은

> **4명이 마법과 물리 시스템을 이용해서 함께 문제를 해결하는 것이 실제로 재미있는가?**

이다.

그래픽 작업 때문에 이 검증 자체가 늦어지지 않도록
작업 우선순위를 관리해야 한다.
