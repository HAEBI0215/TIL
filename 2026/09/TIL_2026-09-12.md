## 🍄 Mushroom Spawn System

### SpawnArea 기반 생성

```text
MushroomSpawnArea
  ↓
영역 크기 확인
  ↓
랜덤 위치 후보 생성
  ↓
유효한 지면인지 검사
  ↓
버섯 생성
```

SpawnArea의 위치와 크기만 바꾸면 버섯 생성 범위를 쉽게 조절할 수 있도록 만드는 것이 목표다.

### 단순 Random Spawn의 문제

- 버섯끼리 서로 겹칠 수 있음
- 특정 위치에 지나치게 몰릴 수 있음
- 자연스러운 분포를 만들기 어려움

따라서 단순 랜덤보다 **최소 거리 조건이 있는 랜덤 분포**가 더 적합하다고 판단했다.

## 📐 자연스러운 랜덤 분포

```text
랜덤 위치 생성
  ↓
기존 생성 위치와 거리 확인
  ↓
최소 거리 이상?
  ↓
YES → 위치 사용
NO  → 다른 위치 탐색
```

이 방식이면 버섯이 랜덤하게 보이면서도 서로 너무 붙지 않도록 만들 수 있다.

### Raycast로 지면 확인

```text
X / Z 위치 선택
  ↓
위에서 아래로 Raycast
  ↓
지면 Hit
  ↓
Hit Position 사용
```

지형 높이가 달라도 실제 지면 위에 버섯을 생성할 수 있다.

## 🧱 Script Architecture

```text
ServerScriptService
├─ ResourceServer
└─ ResourceSpawner

ReplicatedStorage
└─ Modules
   ├─ ResourceData
   └─ SpawnAlgorithm
```

| 구성 | 역할 |
|---|---|
| `ResourceServer` | 자원 생성과 채집 흐름 관리 |
| `ResourceSpawner` | 어떤 자원을 어디에 생성할지 관리 |
| `ResourceData` | 버섯/광석 등의 데이터와 가중치 저장 |
| `SpawnAlgorithm` | 랜덤 위치 계산 |

```text
SpawnAlgorithm
→ 어디에 생성할지 계산

ResourceSpawner
→ 무엇을 생성할지 결정

ResourceServer
→ 게임 상태와 상호작용 관리
```

## 📚 Today I Learned

### 1. 랜덤 생성에는 분포까지 고려해야 한다

단순히 랜덤 좌표를 뽑는 것과 자연스럽게 분포된 결과를 만드는 것은 다르다.

### 2. 알고리즘은 독립된 Module로 분리할 수 있다

순수하게 계산만 담당하는 코드는 게임 데이터나 서버 상태와 분리하면 재사용하기 쉽다.

### 3. Raycast는 지형 기반 스폰에 유용하다

평평하지 않은 맵에서는 X/Z 좌표만 계산하는 것으로 충분하지 않다.

### 4. 채집은 요청보다 검증이 먼저다

멀티플레이 환경에서는 동시에 같은 자원에 접근하는 상황을 고려해야 한다.
