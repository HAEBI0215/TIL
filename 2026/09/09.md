Luau

타입 표기 이해

Luau에서는 Lua 문법을 기반으로 하면서 타입을 추가로 명시할 수 있다.

함수에서 배열 형태의 숫자 데이터를 받고 숫자를 반환하는 경우처럼

입력 타입
    ↓
함수 처리
    ↓
반환 타입

을 코드에 명확하게 표시할 수 있다.

C#의 강한 타입 시스템과 완전히 같은 방식은 아니지만, 규모가 커질수록 어떤 값이 들어오고 나가는지 확인하는 데 도움이 된다.

숫자 for문과 배열 순회의 차이

기존 C#의 for와 foreach 차이를 Luau와 비교하면서 정리했다.

숫자 기반 반복

1
2
3
...
10

처럼 일정 범위의 숫자가 필요할 때 사용한다.

배열 / 테이블 순회

arr 안의 첫 번째 값
arr 안의 두 번째 값
arr 안의 세 번째 값
...

처럼 실제 데이터 묶음 안에 들어 있는 값을 하나씩 사용할 때 적합하다.

for _, n in arr do 형태에서는 실제로 필요한 값만 n으로 받아 사용할 수 있고, 사용하지 않는 인덱스는 _로 표시할 수 있다는 것도 확인했다.

사용자 입력과 배열

고정된 테이블을 직접 코드에 작성하는 것과 사용자에게 입력받아 테이블을 만드는 것은 서로 다른 과정이라는 점도 정리했다.

사용자 입력
    ↓

    ↓
숫자로 변환
    ↓
table에 삽입
    ↓
반복문으로 사용

이 과정을 이해하면서 이후 정올 문제를 Luau로 풀기 위한 기본적인 입력 처리 구조를 익혔다.

Rojo의 동기화 방향 이해

환경을 다시 구성하면서 가장 중요한 점을 하나 확인했다.

Rojo는 기본적으로 VS Code의 파일을 Roblox Studio에 반영하는 워크플로우에 가깝다.

즉 Studio에서 작성한 기존 코드를 수정하면 그것이 자동으로 VS Code 파일로 역동기화되는 구조라고 생각하면 안 된다.

따라서 장기적으로는

VS Code에서 코드 작성
    ↓
Rojo Serve
    ↓
Roblox Studio에 반영

을 기본 개발 흐름으로 사용하는 편이 관리하기 쉽다.

Roblox / Luau 모작

현재는 PLM 데모 목표가 가장 가깝기 때문에 PLM Stage 제작의 우선순위를 가장 높게 두는 것이 적절하다고 판단했다.

Today I Learned

1. for와 foreach의 핵심 차이는 반복의 기준이다

정해진 숫자 범위를 반복할 것인지, 데이터 묶음의 실제 값을 순회할 것인지에 따라 반복문을 선택해야 한다.

문법 모양보다 무엇을 기준으로 반복하는지를 먼저 생각하는 것이 중요하다.

2. 타입 표기는 함수의 의도를 더 명확하게 만든다

Luau에서도 함수가 어떤 데이터를 받고 어떤 데이터를 반환하는지 표시하면 코드의 목적을 빠르게 이해할 수 있다.

특히 ModuleScript가 많아질수록 타입 정보의 가치가 커질 수 있다.

3. 개발 환경이 꼬였을 때는 최소 구조에서 다시 시작하는 것이 빠를 수 있다

Rojo 설정을 계속 덧붙여 수정하다 보면 현재 어느 부분이 문제인지 구분하기 어려워진다.

프로젝트 규모가 아직 작다면 불필요한 설정을 제거하고 가장 기본적인 구조부터 다시 연결하는 방법이 오히려 빠르다.

4. Rojo는 양방향 자동 동기화 도구로 생각하면 안 된다

Studio의 코드를 자동으로 로컬 파일에 저장해주는 구조가 기본이 아니기 때문에, VS Code를 코드의 기준점으로 두고 Studio를 실행·테스트 환경으로 사용하는 개발 방식이 더 자연스럽다.
