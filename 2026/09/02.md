# 🎮 Perfectly Legal Magic

## Animate 이동 방식 개선

기존 Animate 오브젝트는 목표를 향해 이동하면서 회전했지만,

**이동과 회전이 서로 독립적으로 계산되고 있었다.**

때문에 오브젝트가 실제로 굴러간다기보다
바닥 위에서 미끄러지면서 회전하는 것처럼 보이는 문제가 있었다.

내가 원하는 움직임은 사람이 걸을 때 걸음의 크기만큼 앞으로 이동하는 것처럼,

> 오브젝트가 한 면을 굴렀다면
> 그 면의 크기만큼 실제 위치도 이동하는 방식이다.

즉,

```text
기존

이동
+
회전

↓

개선 방향

이동 거리 ↔ 회전량
```

처럼 두 값을 서로 연결해야 한다.

특히 큐브의 경우 한 면에서 다음 면으로 넘어가는 회전이 발생하면
그만큼 실제 위치도 이동하도록 만들어야 자연스럽다.

## 💡 생각한 점

게임에서 자연스러운 움직임을 만들기 위해서는
단순히 애니메이션을 추가하는 것만으로는 부족할 수 있다.

오브젝트가 왜 그렇게 움직이는지를 설명할 수 있는
**일관된 규칙**이 존재하는 것이 중요하다.

Perfectly Legal Magic은 플레이어가 시스템의 규칙을 이해하고
그 규칙을 조합해 퍼즐을 해결하는 게임이기 때문에,

Animate 역시 단순한 이동 마법보다

> **예측 가능한 물리 규칙을 가진 마법**

으로 만드는 것이 게임의 방향과 더 잘 맞는다.

# 🧩 시스템 중심 퍼즐 방향

Perfectly Legal Magic의 핵심 방향도 다시 정리했다.

게임의 목표는

```text
특정 마법 찾기
        ↓
정해진 장소에 사용
        ↓
퍼즐 해결
```

같은 정답형 퍼즐이 아니다.

대신,

```text
마법의 규칙 이해
        ↓
환경과 상호작용
        ↓
여러 시스템 조합
        ↓
플레이어만의 해결법 발견
```

같은 구조를 목표로 한다.

플레이어가

> "이게 된다고?"

라고 느끼는 순간을 많이 만드는 것이 중요하다.

따라서 마법 각각을 단순히 퍼즐을 푸는 도구로 만드는 것이 아니라
다른 마법이나 환경과 자연스럽게 상호작용할 수 있도록 만들어야 한다.

# 🖥️ UIControllGame

## 퍼즐 제작 구조 정리

UIControllGame에서는 앞으로 새로운 퍼즐을 빠르게 추가하기 위해
퍼즐 제작 구조를 정리했다.

퍼즐 하나는 하나의 Prefab으로 관리한다.

```text
Puzzle01.prefab
Puzzle02.prefab
Puzzle03.prefab
...
```

퍼즐은 개발용 Scene에서 개별적으로 제작하고 테스트한 뒤
완성된 Prefab을 최종 Game Scene에 배치하는 방식으로 진행한다.

---

## 🔄 기본 퍼즐 흐름

현재 퍼즐의 기본 흐름은 다음과 같다.

```text
CopyableUI
     ↓
ClipboardManager
     ↓
DraggableUI
     ↓
DropTarget
     ↓
OnDropSuccess
     ↓
성공 조건 검사
     ↓
성공 연출
     ↓
PuzzleManager.CompletePuzzle()
```

### 역할

| 시스템                | 역할                     |
| ------------------ | ---------------------- |
| `CopyableUI`       | 텍스트 또는 데이터를 복사 가능하게 처리 |
| `ClipboardManager` | 복사된 데이터를 클립보드 아이템으로 생성 |
| `DraggableUI`      | 생성된 UI를 드래그할 수 있도록 처리  |
| `DropTarget`       | 특정 UI를 드롭할 수 있는 영역     |
| `OnDropSuccess`    | 정상적인 드롭이 발생했을 때 퍼즐에 전달 |
| 퍼즐 스크립트            | 성공 조건과 퍼즐 연출 처리        |
| `PuzzleManager`    | 퍼즐 완료 상태 관리            |

---

## 💡 공통 시스템과 퍼즐 로직 분리

퍼즐마다

* 복사 기능
* 드래그 기능
* 드롭 기능
* 창 이동 기능

같은 시스템을 다시 구현하지 않는다.

공통 시스템에서 기본적인 UI 상호작용을 담당하고
각 퍼즐은 다음 세 가지만 신경 쓰도록 만든다.

```text
1. 어떤 데이터를 받을 것인가?

2. 언제 성공으로 판단할 것인가?

3. 성공했을 때 무엇을 할 것인가?
```

이렇게 역할을 나누면 새로운 퍼즐을 제작할 때
필요한 코드와 작업량을 크게 줄일 수 있다.

# 📚 Today I Learned

## 1. 이동과 회전은 서로 연결될 수 있다

오브젝트를 굴러가게 만들 때

```text
이동 + 회전
```

두 기능을 단순히 동시에 실행하는 것만으로는
자연스러운 움직임이 만들어지지 않을 수 있다.

물체의 크기와 회전량을 이용해서
실제 이동 거리를 결정해야 더 자연스럽게 보인다.

---

## 2. 게임의 규칙이 곧 콘텐츠가 될 수 있다

Perfectly Legal Magic에서는
개별 퍼즐을 많이 만드는 것만큼이나

**마법 시스템 자체를 재미있게 만드는 것**이 중요하다.

규칙이 단순하고 예측 가능하면 플레이어는 그 규칙을 조합해서
개발자가 직접 준비하지 않은 해결 방법까지 만들어낼 수 있다.

---

## 3. 공통 기능과 개별 콘텐츠는 분리하는 것이 좋다

UIControllGame에서 공통 UI 시스템과 퍼즐 로직을 분리하면서

```text
공통 시스템 = 어떻게 동작하는가

퍼즐 로직 = 언제 성공하는가
```

처럼 역할을 나누는 것이 중요하다는 것을 다시 확인했다.

이렇게 하면 새로운 퍼즐을 추가할 때 기존 시스템을 계속 수정할 필요가 없다.
